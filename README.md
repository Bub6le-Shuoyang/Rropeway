## 项目简介

Rropeway 是一款完全离线运行的游戏对话脚本编辑器。它将传统文档中的连续文本拆分为可组织、可检索、可预览的结构化内容，帮助创作者管理长篇剧情、非线性分支、角色表现和项目素材。

Rropeway 适合以下创作场景：

- 视觉小说、AVG、互动影游与文字冒险
- RPG、叙事解谜及任务对话
- 包含多章节、多场景和条件分支的游戏剧情
- 需要集中维护角色、立绘、物品与剧情素材的个人项目

项目坚持本地优先：剧本、角色、物品和素材保存在用户选择的项目目录中，不依赖云端服务，也不要求联网才能编辑。

## 功能概览

### 剧本编辑

- 使用章节、普通场景和支线场景组织项目
- 在内容流中插入对白、旁白、玩家选择、物品和分段
- 新内容可插入到当前选中项之后，并在对应位置显示创建工具
- 支线可记录触发方式，默认不参与主流程，也可手动加入流程图
- 每个场景拥有独立且可折叠的设计备注，备注不会进入剧情预览
- 按角色筛选当前场景对白，集中校正人物语言风格
- 支持状态标签、关键节点、主视角和创作备注
- 支持文字颜色、粗体、斜体、字号、对齐、字距、段落间距和上方注释
- 支持拖动排序、项目级撤销/重做和全文搜索

### 角色与演出素材

- 维护角色名称、定位、简介、代表色和默认人形
- 每个角色拥有独立的头像组与立绘组，可保存多种表情
- 支持多图导入、默认素材、头像别名和从立绘裁剪头像
- 普通角色与主视角角色在编辑器和预览中采用左右分离布局
- 角色关系图支持双向关系、自由坐标、画布平移、30%–250% 缩放和可编辑便签

### 物品与调查内容

- 建立项目级物品库，维护名称、Tag、图片组、简介、效果和备注
- 按名称与 Tag 检索物品，未归档物品独立分组
- 同一物品可在不同场景中多次插入，每个实例拥有独立调查反应
- 物品内容编辑器复用普通剧本的对白、旁白、选择、物品和分段能力
- 物品内容可以继续嵌套物品，所有实例内容仍归属于所在场景

### 分支、检查与预览

- 玩家选项可关联全项目的“关键节点”对白，并支持搜索和按章节筛选
- 写作检查识别空对白、未设置角色、对白过长、失效素材、缺少立绘、重复关键节点和未关联选项
- 写作统计细化到章节和场景，可从问题列表直接跳转修复
- 全项目流程图支持自由排列场景、设置预览起点、跨章节连接“下一场”并显示选项分支
- 当前场景预览从正在编辑的场景开始，可在预览器中切换场景
- 完整预览按照流程图编排播放，而不是强制使用章节线性顺序
- 分段支持大图轮播，轮播间隔可在偏好设置中调整

### 桌面工作区

- 新建、打开、重命名、删除项目及在资源管理器中打开项目目录
- 最近项目持久化记录；路径失效时提示并清理历史记录
- 已保存项目支持自动保存，异常退出时可恢复临时草稿
- 关闭窗口前提供保存、不保存和取消操作
- 浅色、夜间和跟随系统三种主题
- 两套内置皮肤，并支持背景图、配色、透明度、模糊、圆角、密度和字体自定义
- 可调节和收起的侧栏、可停靠或浮动的编辑面板以及响应式工作区

## 开始使用

### 系统要求

- Windows 10 或 Windows 11（x64）
- 从源码运行时需要 Node.js 与 npm，建议使用当前 LTS 版本

### 安装桌面版

正式安装包发布后，可从 [GitHub Releases](https://github.com/Bub6le-Shuoyang/Rropeway/releases) 下载 `Rropeway-Setup-<版本号>.exe`。

当前尚未发布安装包时，可以按照下方步骤从源码运行。

### 从源码运行

```powershell
git clone https://github.com/Bub6le-Shuoyang/Rropeway.git
cd Rropeway
npm install
npm start
```

应用启动后，可以直接新建项目，或打开已有的 `.scriptroom` 项目入口文件。

## 项目存储

Rropeway 使用“轻量索引 + 内容寻址 JSON 组件 + 原始素材文件”的本地存储结构。`.scriptroom` 只负责指向当前有效组件，不承载整套剧本正文。

```text
项目名称/
├─ 项目名称.scriptroom
├─ 项目名称.scriptroom.backup
├─ project-data/
│  └─ components/
│     ├─ project/
│     ├─ characters/
│     ├─ items/
│     ├─ assets/
│     ├─ relationship-graph/
│     ├─ scene-flow/
│     ├─ chapter-index/
│     ├─ chapters/
│     └─ scenes/
└─ assets/
   ├─ images/
   ├─ audio/
   ├─ items/<物品 ID>/images/
   └─ characters/<角色 ID>/
      ├─ avatars/
      └─ portraits/
```

这种结构带来以下特性：

- 每个场景使用独立 JSON 组件，修改单个场景不会重写整个项目
- 角色、物品、素材索引、关系图和流程图彼此独立
- 组件包含 SHA-256 校验值，读取时会验证完整性
- 保存时先写入新组件，再原子替换 `.scriptroom` 索引
- `.backup` 保留上一份有效索引，主索引损坏时可尝试恢复
- 素材只保存项目内相对路径，复制整个项目目录即可迁移或备份
- 旧版单 JSON 和早期分卷项目仍可打开，并在下一次成功保存时升级

完整格式、保存流程和兼容策略见 [PROJECT_STORAGE.md](./PROJECT_STORAGE.md)。

## 本地优先与数据安全

- Rropeway 不依赖在线账号或云端数据库
- 项目正文和项目素材保存在用户选择的项目目录
- 界面主题、窗口布局和最近项目记录保存在 Electron 本机用户数据目录
- 自定义皮肤背景属于本机偏好，不会写入剧本项目目录
- 删除项目或素材时使用系统回收站，降低误删后的恢复成本

自动保存和备份不能替代长期备份。对于重要项目，建议将完整项目文件夹定期复制到另一块磁盘或版本化备份目录。

## 参与开发

### 开发命令

```powershell
# 安装锁定版本依赖
npm ci

# 启动 Electron 开发版本
npm run dev

# 运行数据格式、存储、流程与检查测试
npm test

# 生成 Windows 解包目录
npm run pack

# 构建 Windows NSIS 安装包
npm run dist
```

构建产物输出到 `dist/`。安装包支持选择安装目录，并创建桌面及开始菜单快捷方式。

### 代码结构

| 文件/目录 | 职责 |
| --- | --- |
| `main.js` | Electron 主进程、窗口生命周期与本地文件 IPC |
| `preload.js` | 隔离渲染进程与主进程的安全 API |
| `app.js` | 编辑器状态、界面渲染和交互流程 |
| `project-format.js` | 项目默认值、标准化和旧字段迁移 |
| `project-files.js` | 组件拆分、校验、原子保存和恢复 |
| `story-flow.js` | 场景流程、支线与预览顺序 |
| `writing-checks.js` | 写作问题扫描和章节/场景统计 |
| `item-format.js` | 物品资料与嵌套内容结构 |
| `skin-settings.js` | 内置皮肤和自定义外观配置 |
| `test/` | Node.js 自动化测试 |

提交改动前，请至少运行：

```powershell
npm test
```
